## Overview

Tables are built from compositional primitives that map directly to [HTML table elements](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/table). Each primitive is a styled wrapper that accepts all native HTML attributes, giving you full control over layout, sizing, and responsiveness.

Rows use CSS Grid with [subgrid](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_grid_layout/Subgrid) for column sizing. Define columns once via the `columns` prop on `<TableContainer>` — all rows share the same column tracks.

- **TableContainer:** Wraps the `<table>` in a scrollable container with elevation styling. Accepts a `columns` prop for CSS Grid column sizing.
- **TableHeader / TableBody / TableFooter:** Semantic section wrappers (`<thead>`, `<tbody>`, `<tfoot>`).
- **TableRow:** A table row (`<tr>`) that inherits column tracks via subgrid.
- **TableRowAction:** Text that names a clickable row, such as a name, made into the row's link or button.
- **TableHead:** A column header cell (`<th>`).
- **TableCell:** A data cell (`<td>`).

## Usage

Import the components:

```tsx
import {
  TableContainer,
  TableHeader,
  TableBody,
  TableRow,
  TableHead,
  TableCell,
} from "@eqtylab/equality";
```

Basic usage:

```tsx
<TableContainer columns="1fr 1fr auto">
  <TableHeader>
    <TableRow>
      <TableHead>Name</TableHead>
      <TableHead>Email</TableHead>
      <TableHead>Role</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableCell>Alice Cooper</TableCell>
      <TableCell>alice@example.com</TableCell>
      <TableCell>Admin</TableCell>
    </TableRow>
  </TableBody>
</TableContainer>
```

## Variants

### Default

A thin line runs between rows, so rows stay easy to tell apart without adding weight. Use this for most tables, and for every table in a card.

### Clickable Rows

A row can open something, such as a page or a sheet. Wrap the text that names the row in `<TableRowAction>`, inside its cell. It becomes the row's link when the row has an `href`, or a button when it only has `onClick`, and it covers the whole row, so a click anywhere on the row opens it. Screen readers announce it where it sits, as "Alice Cooper, link", so it needs no label of its own.

- **`href`** — The URL the row opens. Pass the URL the browser should open, including any basename your router adds. In React Router, `useHref` gives it.
- **`onClick`** — Runs when the row is opened. With `href`, a plain click runs `onClick` instead of following the link, so your router's `navigate` opens the row without reloading the page. <kbd>Cmd</kbd>/<kbd>Ctrl</kbd>, <kbd>Shift</kbd> and middle clicks still open the URL in a new tab or window.

Clickable rows work from the keyboard:

- <kbd>Tab</kbd> reaches each table body's rows as a single stop, starting on
  the first row and returning to the row you left.
- <kbd>Enter</kbd> opens the row.
- <kbd>Up</kbd> and <kbd>Down</kbd> arrows move to the previous and next row,
  and <kbd>Home</kbd> and <kbd>End</kbd> to the first and last.

Buttons, links, menus and form controls in the row keep their own keys, and clicking them doesn't open the row.

Put a row's actions in buttons that show a hover of their own: a button takes its own clicks, and the row stays highlighted while the pointer is over it. Don't put links inside a clickable row, because two places to click make it unclear where a click will go. Make the row itself the link with `href` instead.

<TableDemo client:only="react" variant="clickable" />

#### Usage

```tsx
const navigate = useNavigate();

<TableBody>
  {agents.map((agent) => (
    <TableRow
      key={agent.id}
      href={agentHref(agent)}
      onClick={() => navigate(agentPath(agent))}
    >
      <TableCell>
        <TableRowAction>{agent.name}</TableRowAction>
      </TableCell>
      <TableCell>
        <DropdownMenu>{/* row actions */}</DropdownMenu>
      </TableCell>
    </TableRow>
  ))}
</TableBody>;
```

#### Accessibility

Always wrap the row's name in `TableRowAction`, so screen readers announce that the row can be opened. You don't need to set `hrefLabel`.

```tsx
<TableRow href="/agents/alice">
  <TableCell>
    <TableRowAction>Alice Cooper</TableRowAction>
  </TableCell>
</TableRow>
```

### Selectable Rows

To let users select rows, add a [`Checkbox`](/components/checkbox) in each row's first cell, labelled by the cell that names the row. Screen readers announce the checkbox's state each time it changes. Select rows with the checkbox only, not by clicking the row, so the row's `onClick` stays free to open it if needed. Set `data-state="selected"` on a selected row to highlight it.

<TableDemo client:only="react" variant="selectable" />

#### Usage

```tsx
<TableBody>
  {users.map((user) => (
    <TableRow
      key={user.id}
      data-state={isSelected(user) ? "selected" : undefined}
    >
      <TableCell>
        <Checkbox
          aria-labelledby={`name-${user.id}`}
          checked={isSelected(user)}
          onCheckedChange={() => toggle(user)}
        />
      </TableCell>
      <TableCell id={`name-${user.id}`}>{user.name}</TableCell>
    </TableRow>
  ))}
</TableBody>
```

### Sticky Header

Use the `sticky` prop on `<TableHeader>` to keep column headers visible while scrolling. It accepts two modes:

- **`container`** — the header sticks within the table's own scroll area. The `<TableContainer>` must have a constrained height (e.g. `max-h-*`), which makes it scroll internally.
- **`page`** — the header sticks against the document as the whole page scrolls. No height constraint is needed; use this for full-page data tables. Pin offset can be adjusted with the `--table-sticky-top` CSS variable to clear fixed app chrome.

#### On container

<TableDemo client:only="react" variant="sticky-header" />

#### On page

<TableDemo client:only="react" variant="sticky-header-page-offset" />

#### Usage

```tsx
{
  /* Sticks within a height-constrained, internally scrolling table */
}
<TableContainer columns="1fr 1fr auto" className="max-h-[400px]">
  <TableHeader sticky="container">
    <TableRow>
      <TableHead>Name</TableHead>
      <TableHead>Email</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>{/* rows */}</TableBody>
</TableContainer>;

{
  /* Sticks against the document as the page scrolls */
}
<TableContainer
  columns="1fr 1fr auto"
  style={{ "--table-sticky-top": "100px" }}
>
  <TableHeader sticky="page">{/* … */}</TableHeader>
  <TableBody>{/* rows */}</TableBody>
</TableContainer>;
```

## Column Sizing

The `columns` prop accepts a CSS [`grid-template-columns`](https://developer.mozilla.org/en-US/docs/Web/CSS/grid-template-columns) value. All rows share the same column tracks via CSS subgrid.

### Fixed and Flexible Columns

Mix `fr` units for flexible columns with fixed pixel values for predictable sizing.

<TableDemo client:only="react" variant="column-sizing" />

#### Usage

```tsx
<TableContainer columns="3fr 3fr 100px 100px 60px">
  <TableHeader>
    <TableRow>
      <TableHead>Name</TableHead>
      <TableHead>Email</TableHead>
      <TableHead>Role</TableHead>
      <TableHead>Status</TableHead>
      <TableHead />
    </TableRow>
  </TableHeader>
</TableContainer>
```

### Content-Sized Columns

Use `auto` for columns that should shrink to fit their content. This is useful for action columns or icon-only columns. A row has room for a default `IconButton`, so a row with an actions menu is as tall as one without.

```tsx
<TableContainer columns="1fr 1fr auto auto auto">
```

## Truncation

Use Tailwind's `truncate min-w-0` classes directly on `<TableHead>` and `<TableCell>` to clip overflowing text with an ellipsis. For truncation to work, the column must use `minmax(0, *)` in the `columns` definition so cells can shrink below their content size.

<TableDemo client:only="react" variant="truncation" />

### Usage

```tsx
<TableContainer columns="minmax(0,5fr) minmax(0,8fr) 100px 100px 60px">
  <TableHeader>
    <TableRow>
      <TableHead>Name</TableHead>
      <TableHead className="min-w-0 truncate">Email</TableHead>
      <TableHead>Role</TableHead>
      <TableHead>Status</TableHead>
      <TableHead />
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableCell>Alice Cooper</TableCell>
      <TableCell className="min-w-0 truncate">
        alice.cooper.very.long.email@example.com
      </TableCell>
      <TableCell>Admin</TableCell>
      <TableCell>Active</TableCell>
      <TableCell />
    </TableRow>
  </TableBody>
</TableContainer>
```

## Responsive Columns

Use [container queries](https://tailwindcss.com/docs/responsive-design#what-are-container-queries) to override the `--table-columns` CSS variable at each breakpoint, matching the number of visible columns. Apply `hidden`/`@md:block` on cells for columns that should collapse. Hidden cells are removed from the grid flow, and the remaining visible cells auto-place into the available tracks. Use `className` instead of the `columns` prop so that responsive overrides aren't blocked by inline style specificity.

<TableDemo client:only="react" variant="responsive" />

### Usage

```tsx
<div className="@container">
  <TableContainer className="@md:[--table-columns:1fr_1fr_auto_auto] @lg:[--table-columns:1fr_1fr_auto_auto_auto] [--table-columns:1fr_auto_auto]">
    <TableHeader>
      <TableRow>
        <TableHead>Name</TableHead>
        <TableHead className="@md:block hidden">Email</TableHead>
        <TableHead className="@lg:block hidden">Role</TableHead>
        <TableHead>Status</TableHead>
        <TableHead />
      </TableRow>
    </TableHeader>
    <TableBody>
      <TableRow>
        <TableCell>Alice Cooper</TableCell>
        <TableCell className="@md:block hidden">alice@example.com</TableCell>
        <TableCell className="@lg:block hidden">Admin</TableCell>
        <TableCell>
          <Badge variant="success">Active</Badge>
        </TableCell>
        <TableCell />
      </TableRow>
    </TableBody>
  </TableContainer>
</div>
```

## Inside a row

Every row has room for a small button, so a row with an avatar, a badge or a row action stays the same height as a row of plain text. Rows that hold these line up with rows that don't:

- An avatar: `Avatar` with no `size`.
- A badge: the default `Badge`.
- A switch: `Switch` with `size="sm"`.
- A row action, such as a ⋮ menu: `IconButton` with no `size`.

Anything taller, or text that wraps, makes its row taller. A default-size `Button` makes a regular row 44; a comfortable row stays 44 with a small or default-size button.

A button in a cell reaches into the cell's padding, stopping 4 short of the row's lines. Buttons you stack in one cell, such as a button above a panel it opens, or a row of buttons that wraps onto a second line, then overlap. Give each of them `my-0!`:

```tsx
<TableCell>
  <div className="flex flex-col gap-2">
    <Button className="my-0!">Approve</Button>
    <Button className="my-0!">Reject</Button>
  </div>
</TableCell>
```

To change how much room a cell leaves above and below its content, set `--eq-table-cell-padding` on the cell rather than `py-*`. A button in the cell then still stops 4 short of the row's lines; with `py-*` it can poke out of the cell, and a cell that truncates its text clips it.

```tsx
<TableCell className="[--eq-table-cell-padding:4px]">…</TableCell>
```

For a person with a subline, such as a name over an email, put a [Title Block](/components/title-block) in the cell with an `md` Avatar as its mark, so the avatar sits beside both lines. A medium block sets the email as a caption, so the row is 52 at either density.

<AvatarRowDemo client:only="react" variant="person" />

```tsx
<TableCell>
  <TitleBlock
    titleAs="p"
    mark={
      <Avatar size="md" aria-hidden>
        <AvatarFallback>AC</AvatarFallback>
      </Avatar>
    }
    title="Alice Cooper"
    description="alice@example.com"
  />
</TableCell>
```

Show an ID as plain text when the row's menu or the view it opens can copy it. Keep a `CopyButton` in the cell only when neither can.

<TableDemo client:only="react" variant="with-actions" />

## Density

Rows are `regular` by default. Set `density="comfortable"` for taller rows and header when people read each row slowly, such as a short list of items to review, or when the table is mainly used on touch screens. Keep most tables, and every table in a card, `regular`.

A comfortable row stays 44 with a small or default-size `Button` or `IconButton`. A large one makes it 52.

<TableDemo client:only="react" variant="with-actions" density="comfortable" />

```tsx
<TableContainer density="comfortable" columns="1fr auto auto auto">
  ...
</TableContainer>
```

## Props

### TableContainer

| Name        | Description                                            | Type                                  | Default   | Required |
| ----------- | ------------------------------------------------------ | ------------------------------------- | --------- | -------- |
| `columns`   | CSS `grid-template-columns` value for column sizing    | `string`                              | —         | ❌       |
| `elevation` | Controls the shadow and background styling             | `sunken`, `base`, `raised`, `overlay` | `raised`  | ❌       |
| `border`    | Applies an elevation-aware border with rounded corners | `boolean`                             | `false`   | ❌       |
| `density`   | How tall rows and the header are                       | `regular`, `comfortable`              | `regular` | ❌       |

### TableHeader

| Name     | Description                                                                                                                                    | Type                             | Default | Required |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- | ------- | -------- |
| `sticky` | Pins the header while scrolling. `container` sticks within a height-constrained table; `page` sticks against the document as the page scrolls. | `false \| 'container' \| 'page'` | `false` | ❌       |

### TableRow

| Name        | Description                                                                                                                                                                                           | Type      | Default          | Required |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ---------------- | -------- |
| `clickable` | Applies hover and pointer styles to a row with only `onClick` and no `TableRowAction`, and makes it reachable and openable from the keyboard. A row with `href` or a `TableRowAction` doesn't need it | `boolean` | `false`          | ❌       |
| `href`      | URL the row opens. With `onClick`, a plain click runs `onClick` instead, and a modified click opens the URL in a new tab or window                                                                    | `string`  | —                | ❌       |
| `hrefLabel` | Accessible name for the row's link when the row has no `TableRowAction`                                                                                                                               | `string`  | `"View details"` | ❌       |

### TableRowAction

| Name       | Description                                               | Type        | Default | Required |
| ---------- | --------------------------------------------------------- | ----------- | ------- | -------- |
| `children` | Text that names the row, which becomes its link or button | `ReactNode` | —       | ✅       |
